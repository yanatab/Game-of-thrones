# Кто выживет в «Игре престолов»?

Учебный проект по машинному обучению на основе задания Школы глубокого обучения ФПМИ МФТИ (DLS). Задача состоит в том, чтобы по характеристикам персонажа предсказать, останется ли он жив в мире «Игры престолов».

Вся работа находится в [Jupyter-ноутбуке](Copy_of_hw_1_game_of_thrones.ipynb). Его можно посмотреть прямо на GitHub или [открыть в Google Colab](https://colab.research.google.com/github/yanatab/Game-of-thrones-alive-/blob/main/Copy_of_hw_1_game_of_thrones.ipynb).

## О задаче и данных

Это задача бинарной классификации. Целевая переменная `isAlive` показывает, выжил персонаж или нет. В датасете есть информация о поле, возрасте, популярности, титуле, доме, культуре, семейных связях и появлении в книгах.

Основная сложность оказалась не в самом запуске классификатора, а в подготовке данных: в таблице много пропусков, некоторые категории записаны по-разному, а распределение отдельных числовых признаков сильно несимметрично.

## Что сделано в ноутбуке

### Анализ данных

Сначала я изучила типы столбцов и описательные статистики, проверила пропуски и распределение признаков. Построены графики выживаемости, популярности, возраста и культуры, а также сравнения отдельных характеристик с целевой переменной.

### Предобработка и создание признаков

- `popularity` преобразуется логарифмически, чтобы уменьшить влияние сильно скошенного распределения.
- Из `numDeadRelations` создан бинарный признак `BoolDeadRelations`: есть ли у персонажа умершие связанные персонажи.
- Возраст представлен двумя признаками: `age_value` со значением возраста и `age_no_data`, который показывает отсутствие информации.
- Значения `culture` объединяются в более крупные группы, а для отсутствующих сведений используется отдельная категория `culture_no_data`.

Эти преобразования относятся к feature engineering: мы пытаемся сохранить полезную информацию и сделать признаки удобнее для модели.

### Категориальные признаки

Для признаков `title`, `house` и `culture_grouped` используется `OneHotEncoder`. Параметр `handle_unknown='ignore'` позволяет обрабатывать категории, которых не было в обучающей таблице. Одни и те же преобразования должны применяться к обучающим и тестовым данным.

После подготовки выбирается набор признаков для модели. Не все исследованные и созданные признаки обязательно включаются в итоговую матрицу `X`.

### Обучение модели

В качестве основного классификатора выбрана `LogisticRegression` из Scikit-learn. Исходные данные разделяются на Train и Validation с помощью `train_test_split`. После обучения модель предсказывает классы на валидационной выборке, а качество измеряется метрикой Accuracy.

**Результат, сохраненный в ноутбуке: Validation Accuracy = 0.7949.** Это результат одного разбиения, а не гарантия такого качества на любых новых данных.

Далее модель применяется к отдельному тестовому датасету. В конце ноутбука показана работа с файлом `submission.csv`, который используется как шаблон для итоговых предсказаний.

## Почему логистическая регрессия

Логистическая регрессия подходит как понятная базовая модель бинарной классификации. Она позволяет проверить, насколько информативны подготовленные признаки, без необходимости сразу использовать сложные ансамбли или нейронные сети.
